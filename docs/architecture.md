# Architecture

Status: stub, current as of Sprint 1 (Increment A+B). Will be kept current through each increment
per SR-04 ("`/docs/architecture.md` current as of freeze").

## Shape of the system

No backend server and no database (OOS-07 - a deliberate decision, not a gap: see section 4.2 of
the requirements doc). The frontend talks to the blockchain directly, two ways:

- **Reads** (tally, election state, who's eligible, who's voted): a read-only JSON-RPC provider,
  so results are visible to anyone with the page open - no wallet, no login (FR-12).
- **Writes** (casting a vote, and later: creating an election, registering voters, certifying
  results): the browser's injected wallet (MetaMask) signs and sends the transaction. The user
  pays their own gas; there's no relayer in this sprint's scope (gasless voting is FR-S1, a
  stretch goal).

```
 Voter's browser                          Polygon Amoy testnet
┌─────────────────────┐                  ┌───────────────────────┐
│  Next.js frontend    │  read (RPC)      │  VoterRegistry.sol    │
│  (app/page.tsx)      │ ───────────────> │  ElectionBallot.sol   │
│                       │                  │                       │
│  window.ethereum      │ write (signed tx)│  (Increment C+:        │
│  (MetaMask)           │ ───────────────> │   ElectionFactory,     │
│                       │                  │   ResultsCertification)│
└─────────────────────┘                  └───────────────────────┘
```

## Contracts (this sprint: two of the eventual four)

- **`VoterRegistry.sol`** - the allowlist. `admin` (immutable, set at deploy) can call
  `registerVoters(address[])`; anyone can read `isEligible(address)`. Emits `VoterRegistered` per
  new address.
- **`ElectionBallot.sol`** - one contest, one vote per eligible wallet. A `Draft -> Open -> Closed`
  state machine, `onlyAdmin`-gated `openVoting()`/`closeVoting()`, and `castVote(candidateId)` that
  checks state, eligibility (via the `VoterRegistry` it was constructed with), and
  one-vote-per-wallet, then records the vote and emits `VoteCast(voter, candidateId)`. Both
  contracts are immutable once deployed - no proxy, no upgrade path, no pause/override (CR-04).

Not built yet (by design - see `docs/sprints/sprint-01/requirements.md`):

- **`ElectionFactory.sol`** (Increment C) - deploys and indexes `VoterRegistry`/`ElectionBallot`
  pairs. This is what makes the system permissionless: whoever calls `createElection(...)` becomes
  that election's sole admin, and no other account (including whoever deployed the factory) has
  any authority over it. There is deliberately no system-admin role above this (OOS-14 - logged as
  a decision in `docs/decision-log.md`).
- **`ResultsCertification.sol`** (Increment D) - records the final tally on-chain after an election
  closes, so the public verification page can show "certified result" alongside an independent
  recomputation from raw `VoteCast` events and flag a match or mismatch (FR-13).

## Frontend

Next.js 14 (App Router) + React + TypeScript + ethers.js v6, no server-side API routes.

- `lib/contracts.ts` - provider/contract getters and `describeError()`, which extracts this
  project's `"VeraTally: ..."` revert reasons and turns them into plain-language UI copy (NFR-04).
- `lib/network.ts` - prompts MetaMask to switch to (or add) Polygon Amoy via
  `wallet_switchEthereumChain` / `wallet_addEthereumChain`.
- `app/page.tsx` - the single-page voting UI: connect, see the ballot and live tally (polled every
  5s so it updates without a connected wallet), cast a vote, see pending/success/error status.
- `lib/abi/*.abi.json` - generated by `contracts/scripts/export-abi.js`, which runs automatically
  after `npm run contracts:compile` (an npm `postcompile` hook). Never hand-edit these.

## Running it locally (verified end to end for this sprint)

```
npm ci
npm run contracts:compile      # also exports ABIs to frontend/lib/abi/
npm run contracts:test         # 20/20 passing
npx hardhat node --config contracts/hardhat.config.cjs   # in one terminal, from contracts/
npm run contracts:deploy:local # in another terminal - deploys, registers 2 demo voters, opens voting
# copy the printed addresses into frontend/.env.local (see frontend/.env.local.example)
npm run frontend:dev
```

This exact path - compile, test, deploy to a local Hardhat node, then a full
connect-wallet -> select-candidate -> cast-vote -> confirm -> reload-and-see-it-persisted flow
through the real UI - was verified with a real headless browser (Playwright) driving the real
Next.js dev server against a real local chain, not just contract unit tests.

## Deploying beyond local (not yet done - needs the team's own credentials)

Everything above runs inside this build environment with no real funds or external accounts
involved. Two things need the team to do them, not something this sandbox can do on its own:

1. **Amoy testnet deployment** - fund a throwaway deployer wallet from a Polygon Amoy faucet.
   Copy `contracts/.env.example` to `contracts/.env` (never committed - see NFR-03) and set
   `PRIVATE_KEY` and `DEMO_VOTER_ADDRESSES` (the wallets allowed to vote; the script refuses to
   deploy to Amoy without them). Then run `npm run contracts:deploy:amoy`. It prints the
   `NEXT_PUBLIC_*` values the frontend needs and the two `hardhat verify` commands for Polygonscan
   (CR-05), which need `ETHERSCAN_API_KEY` set; the ballot's constructor arguments are written to
   `contracts/verify-args.amoy.js` for the verify command to read.
2. **Hosting** - connect this repository to a Vercel project (or similar) so the frontend skeleton
   is reachable at a public URL, per Increment A's "frontend skeleton deployed to Vercel" goal and
   the judging-day requirement that the deployment stay up (NFR-07).
